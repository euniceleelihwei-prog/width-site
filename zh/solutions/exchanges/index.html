01

充值告警太多，复核团队忙不过来

只看「有没有连上」，正常用户的充值也会被追到几跳之外的风险地址，大量告警最后都是误报。

DART 怎么解决

  • 每一跳必须先到账、后转出才算关联，时间上倒着流的路径直接排除
  • 看风险资金占比，跳数越远门槛越高，只碰过一点点问题资金的地址不会被一刀切
  • 四档处置：通过、复核、加强尽调、拦截，复核团队只看中间两档

证据某支付公司实测：同一地址，另一款工具判「中低风险、需复核」，DART 判 0 分通过。逐笔拆开，那些风险资金在时间上根本流不过来。

02

因为别家交易所的用户，自己被牵连

交易所热钱包每天和成千上万个地址往来，追到别家交易所再往外追，几乎一定能碰到风险地址。

DART 怎么解决

  • 交易所对手方默认豁免：路径追到其他交易所就停止，不会因为别家交易所的其他用户碰过风险地址牵连到你
  • 制裁筛查等强合规场景，可以按需关闭豁免开关

证据中东某交易所接入后，充提筛查默认开启交易所豁免。

常见问题

交易所常问的问题

交易所对手方豁免会不会漏掉风险？

豁免只针对「路径追到其他交易所就停止」，被筛地址本身命中风险标签、或在到达交易所之前的路径上命中规则，照样计入。制裁筛查等强合规场景可以关闭豁免。

充值和提现应该用同一套规则吗？

不建议。充值看资金来源（流入），提现看资金去向（流出），DART 内置 KYT-IN 和 KYT-OUT 两套规则集，跳数默认流入 3 跳、流出 1 跳，都可以调整。

筛查会不会拖慢入账？

制裁筛查 1 秒内返回。同步调用直接给结果；交易非常活跃的地址追得深时耗时更长，可以改用异步模式，先入账再按结果处置，或先挂起再放行。

新的监管名单出来，要我们自己加规则吗？

不用。新的官方动作由我们做成内置规则集，例如 FinCEN 9714 命令发布当天即上线。你也可以复制规则集自己改。

监管检查时能提供什么材料？

每次筛查都有不可篡改的快照，记录当时的请求参数和完整结果；可以通过 API 批量拉取，生成任意时间段的筛查记录和处置统计。产品手册写明了规则定义和评分公式，可作为内部制度附件。

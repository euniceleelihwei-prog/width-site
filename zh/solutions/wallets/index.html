钱包用户最常遇到的问题

01

用户把U打给了不该打的地址

转出去就追不回来。收款方如果涉及制裁或恐怖融资，用户自己也可能被卷进去。

DART 怎么解决

  • 转账前查收款地址：命中制裁、恐怖融资、诈骗等公开来源时，在确认页给出提示
  • 制裁筛查 1 秒内返回，不卡用户转账

证据某 Web3 社交平台把收款、提款检测做进付费会员，避免用户把U打给恐怖融资地址、触发反恐融资（CFT）风险。

02

收到问题资金，用户自己被连带冻结

收到的U如果来自被发行方冻结、黑客或诈骗的资金，冻结可能落到用户头上，客诉最后落到钱包。

DART 怎么解决

  • 收款后查资金来源：按时间顺序向上游追，只有先到账、后转出的钱才算有关联
  • 来自发行方冻结、黑客、诈骗资金时及时提醒用户

证据稳定币发行方冻结标签已在生产环境使用。

03

风险提示太多，用户不再相信

每笔都弹警告，用户很快就会忽略；误报多了还会流失。

DART 怎么解决

  • 时间上流不过来的路径直接排除，风险资金占比不够的不计入
  • 交易所对手方默认豁免，充提交易所的正常转账不会被误报
  • 四档结论，钱包可以只对高档位弹窗

证据某支付公司实测：另一款工具判「中低风险、需复核」的地址，DART 判 0 分通过，那些风险资金在时间上根本流不过来。

常见问题

钱包常问的问题

转账前检查会不会让用户等很久？

制裁筛查 1 秒内返回。地址筛查同步调用直接给结果；交易非常活跃的地址追得深时，可以用异步模式，不阻塞转账流程。

给用户的提示该怎么写？

建议只说命中了哪类公开来源，例如官方制裁名单、发行方冻结，不给个人地址下「诈骗」「洗钱」这类定性，由用户自己决定是否继续。

自托管钱包没有用户资金，也需要筛查吗？

筛查是给用户的保护：避免把U打给制裁或恐怖融资地址，收到问题资金时及早知道。也有钱包把它做成付费安全功能。

一个地址在多条链上都有余额怎么办？

用全链筛查接口，DART 自动识别该地址在哪些链、哪些币种上有流水，一次筛完，结果按链分开，最差的一条放在最上面。

用户量很大，扛得住吗？

生产环境每天 30–40 万次 API 调用；某头部自托管钱包接入一周内就上到单日 7 万次以上。正式接入前我们按你的量一起评估。

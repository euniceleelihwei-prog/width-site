支付业务的难题

支付公司和U卡发行方常见的问题

01

一笔问题资金，可能连累整条通道

U 一旦进了卡组织和银行通道，问题资金会让合作银行、卡组织重新审视你的整个业务。

DART 怎么解决

  • 充卡、入金前筛资金来源：涉及制裁、发行方冻结、黑客、诈骗资金时分档处置
  • 按时间顺序向上游追，只计算转出前已经到账的钱

证据中东某U卡发行方在充卡前筛查资金来源，不让问题资金进入卡组织和法币通道。

02

要么全拦、要么全放，业务和合规两头为难

只有「通过 / 拒绝」两种结果，拦多了丢客户，放多了担风险。

DART 怎么解决

  • 四档处置：0–19 通过、20–49 复核、50–79 加强尽调、80–100 拦截
  • 加强尽调档请用户补充资金来源说明，而不是直接拒绝
  • 阈值和每条规则的分值都按你的风险偏好调

证据处置档位和规则分值都写在产品手册里，可以直接作为内部制度附件。

03

别的工具报了风险，却说不清为什么

一个「中低风险」的结论，让你既不敢放、也说不出拦的理由。

DART 怎么解决

  • 每一跳必须先到账、后转出才算关联，倒着流的路径直接排除
  • 结果列明命中路径、跳数、金额、占比和加分

证据某支付公司实测：同一地址，另一款工具判「中低风险、需复核」，DART 判 0 分通过。逐笔拆开，那些风险资金在时间上根本流不过来。

常见问题

支付公司常问的问题

合作银行要求「零容忍」，DART 怎么配？

可以把制裁、恐怖融资等类别的规则设为拦截，并调低评分阈值。规则集独立保存，可以清楚说明某个时点用的是哪套规则。

加强尽调档具体怎么处理？

建议请用户补充资金来源说明，再由合规人员结合结果里列出的命中路径、金额和占比判断，而不是直接拒绝。

审计时能拿出什么？

每次筛查都有不可篡改的快照，记录当时的请求参数和完整结果。可以通过 API 批量拉取，生成任意时间段的筛查记录和处置统计。

我们同时接了多家合作银行，规则能分开吗？

能。复制内置规则集，为每家合作方配置一套，筛查时传入对应的规则集即可。

只有稳定币业务，DART 够用吗？

DART 专做 USDT / USDC，覆盖 11 条链。如果你的业务以稳定币为主，可以单独使用；还有其他资产时，可以和现有工具并用，各管各的资产。
